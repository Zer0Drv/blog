# WebSocket 会话有效性（#56）

`/ws` 握手继续使用认证 Cookie 与现有 `JwtDecoder`，应用会话属性只保存用户 ID、`jti` 和 `expiresAt`，不额外保存原始 token。
缺少身份标识、到期时间、已经到期或已进黑名单的凭据拒绝握手。WS 到期检查使用严格 `exp`，不继承 HTTP JWT 校验器的时钟偏差宽限。

连接注册先入表，再复检共享黑名单，避免握手校验后、连接注册前发生吊销导致漏关。
每条通知、私信和 `pong` 发送前均检查会话仍在注册表、连接打开、凭据未到期且未被吊销。
Redis 查询失败时关闭并移除连接，客户端可按既有机制重连或回退 HTTP 轮询。

`TokenService` 在写入黑名单后同步发布吊销事件：单 token 关闭该 `jti` 的所有连接，用户级吊销关闭该用户的连接，包括活跃 token 集合为空时。
发送、鉴权检查与吊销关闭持有同一个 session 锁。本机在吊销开始前已通过校验并进入发送的帧允许完成；吊销调用等待这些发送结束，返回后这些连接不能再开始发送业务帧或心跳。
连接关闭失败仍先移出表；旧迭代快照也必须重新检查表成员资格，不能继续发送。
正常关闭、发送失败与应用退出均会清理连接，注册/移除按用户桶原子执行，避免并发清理丢失新连接。

空闲连接按一秒固定延迟复检，到期或命中共享黑名单后关闭。实际关闭延迟还受调度、Redis 与网络耗时影响；这不取代逐帧鉴权。
每个实例仅管理自己的连接。本机同步事件不跨实例广播，其他实例通过共享 Redis 在下一次发送前或空闲复检时发现吊销。
其他实例在黑名单写入前已通过校验的在途帧可能完成；不承诺跨进程的全局发送/吊销线性化。多实例必须共用 Redis；实时业务消息本身的跨实例广播、refresh rotation 和领域事件总线继续由 #26 跟踪。

回归包括实际嵌入式 HTTP/WS 服务与 JDK WebSocket 客户端：过期、单会话登出、多 token 隔离、封禁/角色变更/改密、重新连接，以及没有本机事件的共享黑名单清理。
服务级测试另覆盖吊销与发送的并发边界、Redis 失败、关闭失败和空集合用户吊销。测试使用既有 H2 与可写黑名单 Redis 替身，不声称完成真实 Redis 或多实例部署验收。
