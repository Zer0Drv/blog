# 附件清理（#22）

部署后端 V16 迁移和新版应用，再部署前端。管理入口为 `/admin/attachments/cleanup`。
所有应用实例必须先升级到支持引用锁的版本，再运行扫描/物理清理；旧实例不参与协调。
功能不自动执行物理删除，由 ADMIN 在管理端逐项操作。

## 生命周期

1. 普通附件删除现在只移出附件库，不立即删除文件，避免破坏正文和历史版本。
2. 管理员扫描本地上传目录，以及启用时的 MinIO 图片桶。仅识别应用生成的
   `yyyyMM/32位小写十六进制UUID.jpg|jpeg|png|gif|webp` 对象；其他文件、目录、符号链接不清理。
3. 文件上传满 24 小时、附件库没有有效记录且没有任何保留引用时，标记 `OBSERVING`。
   文件保持原位置和可访问状态，观察期固定为至少 7 天，从首次完整扫描成功时开始计算。
   反复扫描不缩短或重置未变化对象的观察期。
4. 观察期间可「恢复并保留」：对象标记 `RESTORED`，同对象的已删除附件记录恢复原属主和分组；
   无元数据的孤儿对象也会保留。手动恢复不会在下次扫描再次被标记。
   从附件库再次删除该对象时解除保留，下次扫描重新开始完整观察期。
5. 到期后管理员物理删除。每次执行重新读取全部引用；发现引用则改为 `RETAINED` 并保留文件。
   之后引用消失、重新扫描时，重新开始 7 天观察期。存储位置/指纹/大小变化也重新观察。
6. 已物理删除的 `DELETED` 或已经不存在的 `MISSING` 不可恢复，需重新上传并使用新 URL。

附件库中的有效记录本身属于保留引用，未插入文章的素材不会仅因时间久就被清理。
文章回收站、私密/下架/草稿、全部保留历史版本与 Redis 自动保存草稿都受保护。
另覆盖评论（含回收站）、自定义页面、用户头像/简介、站点配置、友链和私信。
文章引用读取通过 `article.api.ArticleAttachmentReferences`，不跨域依赖 article 内部类型。

引用匹配使用 UUID 文件名，支持旧域名、Markdown/HTML、HTML 实体、URL 编码和草稿 JSON 转义。
跨存储同名对象会同时受到保护，宁可多保留。浏览器尚未提交、且没有附件库记录的本地编辑内容
无法由服务端观测；正常上传会建立附件记录，应先保存/恢复到附件库再引用历史孤儿 URL。

## 并发和故障

扫描和物理删除使用数据库互斥行，内容写入若包含托管文件引用，也在事务内持有同一行锁。
覆盖文章创建/更新、自动保存、页面、评论、个人资料、站点配置、友链和私信；持锁直到事务完成。
清理使用 READ COMMITTED，引用准入使用锁定读，避免 MySQL REPEATABLE READ 下的旧快照。
因此新引用要么先提交并阻止删除，要么在对象清理认领后被拒绝，提示重新上传。
现存版本恢复/回收站恢复只使用已受完整引用快照保护的数据。

删除前先独立提交 `PURGING` 意图，再执行存储删除并提交最终状态。
失败或进程中断会留下可重试意图；不会提前记账，重复操作不会累计两次回收字节。
`PURGING` 阻止新增引用，但文件仍存在时可恢复取消清理。连接恢复后可重试。
如果删除成功后、状态提交前崩溃，再次检查不存在则记为 `MISSING`，不猜测已回收字节。
Redis 不可用/草稿 JSON 损坏/任一存储扫描不完整时，整次扫描不产生标记；清理也停止。
业务响应仅返回通用错误，不暴露基础设施路径、凭据或端点。

存储按记录的 LOCAL/MINIO 定位，指纹包含根目录或 endpoint/bucket 的摘要。
只操作应用的不可变 UUID 对象，不支持外部工具在删除期间覆盖同一个 key 或绕过应用直接改引用表。
本地拒绝链接及越界路径；MinIO 只删除图片桶中的单个托管对象，不操作其他桶或历史版本。
关闭 MinIO 后仍保留它的队列记录，须重新启用且存储可达后才能检查/恢复/清理。

单次扫描上限为 100,000 个托管对象/Redis 草稿；本地遍历亦设上限，超限整体停止，需分区维护。
扫描会在持锁期间读取保留内容；适合个人博客，建议低峰手动运行。

## API（仅 ADMIN）

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/admin/attachments/cleanup?page=1&size=20` | 队列分页，size 1–100 |
| GET | `/admin/attachments/cleanup/report` | 状态对象数/逻辑大小、已确认回收字节 |
| POST | `/admin/attachments/cleanup/scan` | 完整扫描并标记，返回 scanned/protected/marked |
| POST | `/admin/attachments/cleanup/{id}/restore` | 恢复保留对象及其附件库记录 |
| DELETE | `/admin/attachments/cleanup/{id}` | 到期后复核并删除；也用于故障重试 |

队列保存最近操作员、时间、错误状态、对象指纹和确认回收字节。报表统计成功删除对象的逻辑大小，
不等同于实际磁盘可用空间：MinIO 的版本保留、保留策略及去重可能改变实际回收量。
运维备份/历史版本清理仍使用独立流程。

## 验证

`AttachmentCleanupIntegrationTests` 使用真实 Spring 安全链、H2 事务与临时目录，覆盖保留来源、
观察期、恢复、并发内容写入与清理、幂等、失败重试与拒绝再次引用；Redis 以桩验证草稿及故障。
`AttachmentObjectStoreTest` 覆盖临时磁盘与 MinIO SDK 桩的枚举/检查/删除、缺失与权限失败区分、
替换检测和存储位置变更；CI 另使用真实 MySQL 校验 Flyway V16。
真实 Redis/MinIO 跨进程故障演练不在此测试套件中。
