# 文章修改草稿与编辑冲突（#93）

V22 为 `article` 增加 `edit_revision`，并新增每篇文章一条的 `article_working_copy`。`article` 始终保存生效稿；工作稿只供作者和管理员读取。列表、搜索、Feed、SEO、导出和系列目录继续读取生效稿，不连接工作稿表。

## 编辑与发布

- 已发布文章（包括尚未到时间的定时文章、密码文章和私密文章）手动保存只更新工作稿。自动保存也写入数据库，刷新或重新登录后仍可继续编辑，没有 Redis TTL。
- 草稿和下架文章的手动保存更新其未公开的正文；自动保存仍写工作稿。保存不改变文章生命周期，只有明确发布操作才提交当前完整表单。
- 更新发布在同一事务中替换正文、标题、摘要、slug、分类、标签、封面及可见性，保存旧生效稿版本并清除工作稿。已经发布的文章保留原发布时间，包括既有定时计划。下架后的再次发布默认保留已有发布时间；尚未到点的下架文章可以重新指定未来时间。
- 放弃修改删除工作稿并返回生效稿。已发布文章恢复历史版本只生成工作稿，需再次更新发布。历史快照仅含标题、摘要、正文、编辑器类型、封面和分类；恢复时其余字段取当前生效稿，不恢复历史标签、slug、可见性或发布状态。
- 密码只存 BCrypt 哈希，编辑详情仅返回 `passwordConfigured`。空密码保留现有哈希；自动保存允许尚未设置密码的临时 PASSWORD 工作稿，手动保存和发布要求有效密码。明文密码不存入浏览器本地草稿或旧 Redis 草稿。
- 工作稿为文章共享的编辑版本，作者和管理员编辑同一篇文章会进行相同的冲突校验。工作稿附件计入引用保护，回收站保留引用，彻底删除时同事务清理工作稿。

## HTTP 契约

沿用 `Result` envelope。修订冲突为业务码 `40901`（HTTP 200），缺少或负数 `editRevision` 为参数错误。安全链和方法权限仍限制 AUTHOR/ADMIN，业务层继续校验本人或管理员。

| 方法与路径 | 行为 |
| --- | --- |
| GET `/articles/{id}/editing` | 私有编辑详情，优先返回持久工作稿 |
| PUT `/articles/{id}` | 完整保存；已发布文章只写工作稿 |
| POST `/articles/{id}/publish` | 原子发布当前完整表单，清除工作稿 |
| PUT `/articles/{id}/autosave` | 持久自动保存，允许标题或正文暂时为空 |
| DELETE `/articles/{id}/working-copy?editRevision=…` | 放弃工作稿并推进修订号 |
| POST `/articles/{id}/restore/{version}?editRevision=…` | 将历史内容恢复到编辑稿 |
| GET `/articles/{id}/autosave` | 仅兼容读取旧 Redis 草稿，返回 `legacy=true`，不含密码 |

保存、自动保存和发布请求体包含完整编辑字段与 `editRevision`；恢复、放弃操作使用查询参数。成功后返回编辑详情，包含 `editRevision`、`hasWorkingCopy`、`workingCopyUpdatedAt`、`activeStatus`、`activeTitle`、`activeVisibility`、`activePublishTime` 和 `passwordConfigured`。前端以成功响应更新修订号，自动保存响应不覆盖正在输入的正文。

文章行锁串行化保存、恢复和发布；持锁后比对修订号，旧修订不能覆盖服务器版本。下架、回收站删除/恢复和管理员强制下架也推进修订号，阅读计数不推进。前端冲突时保留本地输入，暂停自动保存并提供正文对比及显式重新加载。已有工作稿的文章不能经列表状态接口直接发布，需进入编辑器检查并发布。

## 旧稿兼容与部署

升级不自动把 Redis 草稿变成工作稿。没有持久工作稿时，编辑器可提示用户显式恢复旧 Redis 草稿；存在持久工作稿时不覆盖它。手动保存、发布、放弃和版本恢复提交后清除当前操作者的旧 Redis 草稿，其他操作者遗留的数据也不会自动合并。新建且尚无文章 ID 的本地自动保存继续使用浏览器存储。

先部署含 V22 的后端，再部署配套前端。旧编辑器不发送修订号，其修改请求会被拒绝；升级窗口应提示重新加载页面。不可将旧客户端请求补成最新修订号，否则会绕过冲突保护。

V22 为增量迁移，已有文章修订号初始化为 0，不修改生效内容。备份必须包含工作稿表。回滚旧后端会恢复旧的直接覆盖编辑语义，且旧附件清理器不识别工作稿引用；若必须回滚，应暂停文章编辑和附件清理，保留新增列及表，待恢复新版后继续工作稿。禁止通过 DROP 表清除用户未发布内容。

验证覆盖 H2 权限与生命周期、真实 MySQL 并发和事务回滚、迁移与备份恢复，以及真实浏览器的刷新恢复、移动端预览、冲突对比、放弃和历史恢复。执行方式沿用 [真实依赖测试](real-dependency-tests.md) 与 [浏览器夹具](browser-e2e-fixture.md)。
